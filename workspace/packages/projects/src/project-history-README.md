# Project history and stable sources

`source-reference-types.ts` is the shared browser-safe native source definition. `native-source.ts` validates and serializes it without dropping fields and supplies the actual DSH tool Schema. `native-source-host.ts` mints event references using the same canonical JSON representation. Communication saved-part references retain their existing holder, snapshot and part protocol.

New references identify the logical Project session, actual native Session and header creation identity, canonical logical format, exact event position/type and digest. Canonical format 4 is not a physical predecessor's coordinate system. A mismatched event or unsupported format is never read by reusing its number in another event space. Legacy message locators resolve in their original consumed-message domain; queue-only conflicting versions or multiple consumed records are ambiguous. A legacy tool locator may return the linked records of one real call occurrence, each with an exact source; repeated distinct occurrences are ambiguous.

`readRetainedProjectNativePrefix` verifies Projects ownership and source disposition. A live read joins the existing Session flush barrier and then reads the actual persistence handle. A missing, false or failed durability barrier is reported as unavailable. Cold reads use the real persisted prefix, excluding observation-only recovery events. Reads do not create an Agent, call a provider, execute old tools or alter communication state.

`ProjectHistoryReader` searches retained carrier records, including multiple carriers with the same logical session ID. Queries use native event record time, literal case-insensitive text matching, explicit producer and record-kind filters. Search groups only entries sharing both hostSessionId and messageId; entries without messageId stay separate, and equal text or attemptId never merges messages. A single event must satisfy all query conditions. Groups are ordered by their last saved stage in the frozen cut, while the row's text, time and exact source remain the latest actually matching event. `messageGroup.representativeIsLatest` distinguishes earlier-version matches, and `latestRecordedTime` identifies the group's separate ordering time.

Pages freeze the query, carrier set, prefix identity and ordering. New v3 cursors distinguish the `messages` and `message-versions` views. Each group's `versionsCursor` opens all of its saved stages at that same cut; version pages mark `matchesSearch`, and continue with their own `nextCursor`. V1/v2 cursors retain their original event-list continuation semantics. Default/max page sizes are 20/100 candidates or event versions; search excerpts are at most 256 Unicode code points. Message boundaries are metadata-only: continuation skips already-passed groups before body reads. Selected message bodies stream one version at a time; one query-local relation preparation decorates only retained candidates. Progress without a message ID keeps the existing incremental fold. Context defaults to one preceding and following entry, at most ten each; cross-carrier context follows only recorded carrier sequence.

The UI `queryHistory` / `readHistory` paths select a trusted `chat/v1` projection; Model/Bot/default readers retain the raw saved-history view. Filtering, ordinary-message grouping, keyword matching and page selection happen in the chat candidate space before pagination. Human inputs, assistant visible text/attachments and verified prepared/received Project communications are ordinary results. Tool-only output, control JSON and cumulative progress stages do not become separate chat messages. Explicit settlement/attempt identity suppresses completed prefixes and groups an unfinished attempt at its latest actual saved range; an explicitly cited old source still reads that exact old prefix. Message-id edit/version searches retain the latest actual matching saved version and frozen version cursors. Cursor view identity is checked in both directions.

UI-only `item.chat` carries readable text/blocks and its own Unicode `excerpt`; `match.field=chat.text` names that coordinate space. Raw `item.text`, source/body fields and their ranges retain their original meaning. Communication reads additionally retain each actual Agent-note / forwarded-original group and speaker in `chat.communication.parts`, whose Unicode ranges refer to the complete chat text across all read pages; query omits those section ranges and localized labels never enter searchable text. Search chat text is limited to 256 code points with no copied full blocks. UI exact reads use the same verified full target inside the retained directory operation, then emit at most 4096 chat code points. `chatTextStart` continues that exact target through the same UI RPC; it is absent from model tool arguments. `chat.kind=incomplete-reply` means an actual saved incomplete reply; text paging alone does not change that kind. Global UI partial/limitations cover unavailable sources and actual missing visible blocks, while saved reply incompleteness and intentional body ranges remain on the relevant item. Adjacent context counts chat messages along retained carrier sequence; only actual tools inside that bounded event window are supplied for folded details (at most 20 items / 16384 text points). Stop/control facts stay in raw history.

The UI query also opts into transient `displaySummary` parts. The full source is parsed with the native renderer's GFM libraries before clipping, replacing reserved-host session-link destinations with their decoded labels; URI-only links use a localized UI placeholder. Presentation ownership does not grant navigation authorization or require a complete navigable target. Reference definitions are not visible summary text. When an actual saved partial source leaves dangling outer Markdown next to a GFM-recognized owned URI, its preview is an explicit localized fragment notice; the original partial state and exact original remain available. An excerpt cut from a complete source does not trigger that fallback. Code, external links and ordinary text retain their existing source presentation. The panel bounds the localized display to 256 Unicode code points and keeps whole-row exact-source reading. `text`, `excerpt`, `match`, saved bodies and source identities remain unchanged; display parts are not a source coordinate space. The option is absent from public requests/cursors, and work tools, Bot readers and retained model same-page results omit presentation parts.

Ordinary reads retain bounded visible bodies and stable body references. `native-content.ts` uses the communication canonical JSON encoding and Unicode code-point units, with default/max content pages of 4096/16384. Body and candidate cursors have different formats. Content pages retain the exact source and body digest; post-execute retention must use the corresponding finalizer, which preserves an actual spill location and same-page recovery instead of skipping unreturned text. Raw canonical tool values remain stored by the native owner and are not automatically exposed to ordinary chat reading.

`relatedSources` contains finite navigation links rather than every member of a message/attempt group. Each key contributes its immediate previous/next saved versions (at most four distinct links across message and attempt keys). Tool records use the previous/next records plus their exact start-event occurrence; the call retains a link to its proposal, and an exact proposal read returns its real chain links. A reused tool call ID cannot join another occurrence. Links carry only exact event references, not copied bodies or nested relations; following an unread link does not mean that body's text was delivered. Original progress deltas and each saved cumulative version remain readable. Relation construction indexes the groups once instead of scanning the complete projection for every item. This removes quadratic relation metadata from search, exact read and body-read preparation; it does not add storage I/O paging or change the new-main-Session history selection.

Focused regression tests are `native-source.test.ts` and `chat-history-v2.test.ts`. They include real JSONL persistence and Session observations, fixed queries, exact versions, carrier context, output attempts, independent content paging, durability failures and synthetic-recovery exclusion. Communication content, saved-read and queue-focus tests cover the existing composition. These tests do not establish installed default exports, complete Host/Harness acceptance, model understanding or business adoption.
