# Projects present results

`installProjectPresentedFiles(ctx, ports)` mounts the stock `present` tool result row and the delivered-file cards in the private Projects Conversation. `ports.openFile` is required and receives the original physical Session id and original logged file path. Its real owner is the unified Projects FileReader. A replaced Session binding, disposed owner, or rejected preview remains a failure on the card.

The shared stock `deliverablesDefinition` is retained, including successful mutation paths and the latest `workspace/changes` announcement. `changesForClosing` and the other pure readers in `turn-deliverables.ts` can be consumed by a separate changes-card module. This module registers the definition once and registers the complete stock `deliverables` dictionary; companion cards reuse that namespace.

The turn accumulator preserves every original event sequence and array index, including gaps caused by invalid file entries. Cards select only declarations strictly before the closing reply and keep the last declaration of each exact path in first-seen path order. File content remains at its source path and is read when opened; the card does not claim an immutable copy.

Each card keeps a content reader action (HTML/HTM/XHTML explicitly says “View source”) and adds “Open to use”. The latter uses the optional `externalFiles` port to call the serving Host’s existing `canOpenWorkspacePath` / `openWorkspacePath` default-application operation. Relative paths require the original Session’s known workspace directory; unknown directories fail instead of guessing the Host process cwd. The captured Session binding is checked before capability lookup and again before opening. The Host retains its desktop availability, canonical path mapping, permission, cancellation and native-opener checks. Success means the Host accepted the open request, not that the resulting application was used successfully. Remote files stay on their serving Host. The result receipt's `nativeOpen` reports whether this port is connected, not a cached claim that a desktop is available.

Content remains at its original path, and the unified FileReader's range, navigation and focus behavior are unchanged. The stock file card has no download control (`download: false`). The optional `readFileBytes` type describes the existing private bytes capability for a unified FileReader adapter; this card module does not invoke it or claim that binary rendering is validated.

No `fetch`, native-open HTTP route, settings writer, embedded execution or Cordis management surface is used. The existing outer Host Remote is exposed only through the explicit default-application port. `SOURCES.json` records the MIT upstream files and hashes at `639ed015397290b3745d163aafe02ffee4aa3f84`. Local changes inject the exact private FileReader callback and the explicit serving-Host opener.
