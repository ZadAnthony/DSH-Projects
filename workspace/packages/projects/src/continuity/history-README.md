# Main continuity history

`MainContinuityHistory` reads existing ProjectStore carrier relations through `ProjectsCoreAccess.readNativePrefix` and the shared visible-record projection. It owns no chat database, Session, Agent, message queue, summary or Memory batch. Native prefix reads confirm persistence and exclude the observation-only interrupted closer. Store source disposition and exact creation identity remain authoritative.

`select(projectId, mainSessionId, through, signal)` inspects the bound main's carriers in recorded sequence, ending at the exact real turn cut. A selected turn has a matching native start/end, a completed reason and at least one consumed business input. Primary input, steering, tool steps and retries remain one turn. Empty wakes, imported history, current context and management-only records do not create additional turns. `turns.length` reports the actual number, up to three. `selectionComplete` reports whether an unavailable or changed source left a gap; fewer than three available turns has its own limitation. Unfinished/non-normal turns, pending inbox input and unresolved tool outcomes are separate facts, never additional completed turns.

Known unresolved operations earlier than the three-turn boundary in an already inspected prefix retain only technical state, observation cut, exact sources and read entries. Their earlier business bodies are not copied as another turn, and this check does not trigger a scan of older carriers. Native `TOOL_OUTCOME_UNKNOWN` repairs remain unknown outcomes even though a model-facing error result exists. A later recorded raw return changes the observed state to returned-but-not-delivered; an earlier fixed cut still reports the earlier unknown fact. Nested PTC dispatches keep their own start and parent/root identities. A recorded execution start is a past fact, not a claim that the operation is still running.

Each request history entry is a Projects-produced, read-only recall message containing canonical JSON. Its ordered records retain original roles, visible blocks, producer facts, source versions, header identity, event order and tool associations. Original tools are quoted data, not native tool-call blocks. Hidden reasoning and private tool values follow the existing chat visibility rules. Historical messages never enter Inbox or become native business `user/message` events, and their provenance remains `historical-evidence`. Current configuration and Memory validity still come from their existing request-time owners.

`directory` derives current, previous and all recorded main-carrier entries from Store. Each entry has its existing search parameters and source disposition; a failed observed native source is reported individually rather than removed. `reader(projectId, mainSessionId)` binds search, exact read and body continuation to this main. Native sources must identify its own carrier. Saved communication uses its holder and creation identity; part origins never grant access to execution or other-project history. The existing native and saved-content readers own source decoding, cursor identity, Unicode ranges, retention and failure results.

`fit(window, capacity, signal)` uses the caller's asynchronous measurement of the complete actual request, including all non-history input. It first offers full original delivery. If that request does not fit, it replaces whole quoted turn bodies with explicit unread-body manifests, preserving original record identities and complete source entries. It never truncates JSON, tool arguments or results into apparent valid calls. A manifest reports zero delivered body code points, the selected/undelivered ranges and a stable `read_content` entry for the same body from its beginning. Actual body pages provide their own same-page and next-page cursors. If even the manifests do not fit, preparation fails explicitly.

The final `window-state` entry preserves the requested/available turn count, selection gaps and limitations through the Projects import and every literal request. `fitImported` uses that same canonical saved payload after reopening without fabricating a `MainHistoryWindow`. Stable `history.source` describes the original positions and sources; it makes no delivery-complete claim. Actual delivery fields live in the canonical message and window-state text, which content-only projections preserve in the final literal.

`history-request.ts` exports `prepareMainHistoryRequestProjection(holder, imported, fitImported, options?)` for the shared request installer. Internal `representation: 'minimum'` asks each original producer for its legal minimum manifests; the shared installer first meters their combined minimum and then restores original bodies in actual candidate message order using each producer's existing fitter. This prevents one producer's complete body from prematurely rejecting another producer's legal partial representation. The helper validates imported literal identities, measures the entire composed candidate through the plugin complete-candidate meter, accounts for actual reserved output and returns only same-ID content overrides. System, tool schemas, current blocks, real new input, source provenance, ordering and final compaction suffix remain in the same candidate. The same projector reaches first business requests, continuation/retry, compaction and cold-open paths; an empty prepared preview alone does not establish those consumer results.

Capacity never changes the selected `turns` or their original `items`. Consumers render `sourcedHistory`; they must not reinsert `turns.items` after fitting. The `sources`, `complete` and `limitations` passed to each capacity measurement are exactly the values returned for that candidate. Unread body links and directory entries are not original-body evidence receipts. `complete` reports actual visible-original delivery, independently of the selected-turn count and known operation outcome.

## Model Experience

The model receives a finite recent original-history window, explicit past-record attribution and exact main-scoped discovery/read entries. Default delivery preserves all available visible original text. Partial delivery is capacity-driven and carries continuation entries; it does not add a model summary request, Memory flush, business wake or tool execution. The reader does not judge the value of records or whether three turns are sufficient for a task.

## Known Limitations and Deferred Work

This module does not prove normal installed exports, provider serialization, management-Bot tool composition or native prepared-history persistence. Those belong to the shared request/runtime integration and final same-version acceptance. The focused `continuity-history.test.ts` uses actual ProjectStore, native SessionStore, JSONL persistence and Session-query reads with synthetic data and no model calls. Its helper case uses the plugin source planner and actual token meter to inspect a complete prospective request; it does not dispatch that request, install a profile or claim native-import persistence. Model understanding and actual usage effects remain unverified.
